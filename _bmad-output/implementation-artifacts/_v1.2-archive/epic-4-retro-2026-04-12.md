## What Went Well

- **Fourth consecutive 100% epic completion** — the process is now validated across Epics 1–4 at steadily increasing integration complexity.
- **All 3 Epic 3 prep items completed before Epic 4 started** — `folderId` metadata sync on move (unblocked 4.1), SSE spike (unblocked 4.2), citation responsive pattern (informed 4.1 UI). Prep-first discipline held.
- **Incremental composable growth** — `useChat` was extended for streaming (4.2), model selection (4.3), and conversation persistence (4.4) without being rewritten. "Extend, don't replace" played out.
- **Progressive review severity curve** — 4.1 needed 7 fixes, 4.2 needed 5, 4.3 needed 6, 4.4 needed 0 patches. Pattern of repeated review signals hardened the composable over the epic.
- **Convex-as-source-of-truth migration was clean** — story 4.4 flipped chat from "ephemeral Vue state" to Convex-backed with zero regressions to 4.1–4.3 behavior. The reactive query model carried over from folders/documents without bespoke infrastructure.
- **Security model stayed uniform** — every new function derives `userId` from `identity.tokenIdentifier`; no handler accepts `userId` as an argument; ownership checks precede every read/write. Cross-user isolation tests pass across conversations, messages, and (unchanged) folders/documents.
- **Per-message sources instead of per-conversation** — matches the UI (per-message citations), preserves audit trail, no bespoke join logic.

## Challenges

- **Skipped component tests for Reka UI portaled content** — sidebar-recent-chats and chat-new-conversation tests shipped `.skip` (same as 4.3). The `mountSuspended` + Reka portal pattern is still unsolved for this repo. Convex integration tests cover the data path well, but UI interaction coverage remains a gap.
- **Silent message-persist failures are accepted** — `useChat.sendMessage` fires `persistMessage` without awaiting. If the user mutation fails, the UI shows the message but DB doesn't. The story documents this as an explicit tradeoff ("do not block the UI push"), but it's a correctness risk surfaced in the 4.4 review.
- **Model fallback debt stayed pre-existing** — Story 4.3 centralized the models allowlist only for the `/app/folders/[id]` chat page. The older `/app/chat` page still uses native `<select>` and `useRag` with no fallback. Explicitly deferred; revisit when that page is upgraded or deprecated.
- **Story 4.3 had the highest dismissed-findings count (10)** — most dismissals were architectural (SSE shape, dynamic imports, composable responsibilities). Review signal worked, but the volume indicates scope-boundary clarity could be sharpened for future reviewers.
- **Base-branch ambiguity caught at PR time for 4.4** — local `main` diverges from the integration trunk (`dev`). Not a technical regression, but the orchestrator halted; could be surfaced earlier (e.g., a project convention note in CLAUDE.md).

## Key Insights

1. **Composable extension > composable replacement** — `useChat` absorbed streaming, model selection, and persistence across three stories. The guardrail against parallel composables (`useConversation`, etc.) prevented fragmentation.
2. **Convex reactivity is sufficient for the sidebar** — no Pinia store, no REST layer, no bespoke subscription plumbing. The folders/documents pattern ported cleanly to conversations. This is a repeatable recipe.
3. **Denormalizing `userId` onto messages is worth it** — cheap auth on bulk reads + explicit alignment with the "every query filters by userId" architecture rule. Storage cost is negligible compared to safety clarity.
4. **System `_creationTime` is the right ordering primitive** — no manual timestamps added; reload-time ordering is stable and doesn't require backfill.
5. **Skipped tests now have a pattern debt** — three stories (4.3 + 4.4) shipped with skipped Reka-portal component tests. Prep item for a dedicated fix is overdue.
6. **Branching convention deserved explicit documentation** — saved to user memory (`project_branching_convention.md`). PRs target `dev`; `main` is production, merged manually. Prevents re-litigation.
