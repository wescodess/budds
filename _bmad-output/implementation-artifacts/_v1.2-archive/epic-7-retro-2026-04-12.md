- **Atomic card deletion with denormalised-count integrity** (7-3). `flashcards.deleteCard` patches `flashcardSets.cardCount` in the same transaction as the child-row delete, floored at zero; `flashcards.deleteSet` iterates `by_setId` in 500-row batches, returns `{ deletedCards }` for assertion, then removes the parent. ## Challenges

- **Five new deferred items from 7-1.** None are blockers, but the cluster tells a story: the first story of a new domain carries more review surface than follow-on stories. 7-1 introduced a new POST endpoint, a new LLM prompt, a new Convex table pair, and a new export schema. 7-2/7-3 reused all of it and deferred nothing.
- **Cross-folder `sourceDocumentId` tolerance is a latent provenance risk.** `createSetWithCards` accepts any same-user document, not only documents inside the target folder. Not a tenant leak (ownership still enforced), but a fabricated-but-valid document ID from the LLM could produce a card whose "source" sits outside the folder the user generated from. Realistic risk is near-zero; surfaces a bigger design question for V1.3: should cross-folder sets be first-class?
- **Out-of-range `sourceIndex` silently falls back** (7-1 `generate.post.ts:61` — `chunks[c.sourceIndex] ?? chunks[index] ?? chunks[0]!`). If the LLM hallucinates an index, the card text ends up citing a mismatched chunk with no observability. Single `console.warn` on first out-of-range hit per request would restore triage signal.
- **Generate endpoint has no rate limit** (7-1). Cost-bearing path (AI Search + AI Gateway). Parity with `/api/quiz/generate` and `/api/export/me` — none of them are rate-limited yet. Accepted V1.2 state; pre-GA must add a global abuse guard across all three cost-bearing endpoints in one PR rather than each endpoint separately.
- **The trailing-comma regex `,(\s*[}\]])` is technically over-broad** in `flashcard-prompt.ts#tryJsonParse`. Could in theory strip a `,]` inside a quoted string. Realistic LLM-output risk is near-zero; the pragmatic answer is "swap in a tolerant-parser dep if reliability degrades" rather than hand-roll a robust regex.
- **No `pnpm lint` / `pnpm typecheck` scripts** — carried forward for the third consecutive epic (Epic 5 prep #4 → Epic 6 prep #3 → Epic 7 prep #3). Story-runner verdicts still write `lint_pass: null` / `typecheck_pass: null` every time. Not blocking, but **this is the one Epic 5 retro prep item that has drifted across three epics with no owner pickup**. Pre-GA it becomes a checklist requirement.
- **SRS / per-card rating is explicitly out of V1.2.** 7-2 shipped a pure "flip + Next/Previous" flow; no "easy/medium/hard", no review history, no schedule. This is an intentional product call (7-1 Dev Notes), but it is the largest piece of user-facing functionality the original flashcard PRD anticipated that did not land in V1.x. Carried to V1.3 as a product decision, not engineering debt.

## Key Insights

1. **First-story-in-domain vs follow-on-story deferred-item asymmetry is a generalisable pattern.** Epic 6 had this same shape: 6-1 carried the weight (prompt utility, new tables, export migration, cascade re-audit, baseline triage); 6-2 / 6-3 were mostly UI on established plumbing and deferred zero items. Epic 7 repeats it exactly: 7-1 carried five deferred, 7-2 / 7-3 deferred zero. **The code review budget for an epic should be front-loaded into the first story, not spread evenly.** Story-runner retry allowance should probably mirror this (more lenient on story 1, stricter on follow-ons).
2. **A baseline can be stale-path, not stale-logic.** The chat-input 6-failure baseline looked like a test-infrastructure problem for the whole of Epic 6; it was actually an import rename that never propagated to the test file. The lesson: before scheduling a triage, grep for the symbol the test imports. Five minutes of investigation saves a retro prep item.
3. **One migration per epic is achievable when the first story owns the data shape fully.** Epic 6 needed three migrations (6-1: quizzes + quizQuestions, 6-2: quizAttempts, 6-3: no-op). Epic 7 needed one (7-1: flashcardSets + flashcards). Difference: 7-1's Dev Notes explicitly ruled SRS / per-card rating / attempt-history out of V1.2, locking the data shape before any story shipped. **Ruling out future schema additions in story 1 is cheaper than rolling migrations forward across stories.**
4. **The "in-tab mutually-exclusive panels" pattern is now epic-agnostic.** Quiz Tab hosts `Preview / Take / Edit` off `{ activeQuizId, editingQuizId }`; Flash Cards Tab hosts `List / Study / Editor` off `{ activeSetId, editingSetId }`. Same mechanic, same SSR-friendliness, same no-route-change behavior, same zero-hydration-mismatch. Promote to a V1.x UI pattern note.
5. **CSS-only accessibility beats JS-reactive accessibility when the DOM doesn't need to know.** 7-2's `prefers-reduced-motion` via `@media` query is the canonical example: the browser handles OS-level changes without a Vue re-render, without a listener, without a ref. Reach for JS detection only when a component behavior (not just a style) needs to branch.
6. **The `listByFolder` + `getSetWithCards` reactivity loop made client-side count tracking unnecessary in 7-3.** No `cardCount--` in the client; the atomic transaction on the server + Convex reactivity was the entire integration. Generalise: **if a server mutation adjusts a denormalised count in the same transaction as the authoritative change, the client should read the count, never compute it.**
7. **Dirty-workspace-on-resume is now a solved class of escalation.** Orchestrator hit it at 4-4 (committed WIP, ran runner, merged) and again at 7-3 (same pattern). Recommended default is stable; the escalation is informational rather than decisional. Next revision of the orchestrator spec should demote this to an auto-decision (commit WIP on resume if branch name matches `current_story`).
8. **Closing V1.2 without a single `.skip` deferred over from prior epics is the long-tail win of the Epic 6 retro baseline rule.** "Triage known-red baselines in the first story that runs the failing suite" — applied to `documentActions` in 6-1 (closed), `chat-input` in 7-1 (closed). Zero unresolved red baselines at the V1.2 boundary.
