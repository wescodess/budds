---

## Challenges

- **Emit wiring blind spot** — Child component emits without parent handlers hit both stories. Story 2.1: `createSubfolder` emit never handled in `default.vue`. Story 2.2: had to wire `rename` and `delete` emits following the same fix pattern. No systematic verification that every emit has a handler.
- **Validation inconsistency across mutations** — `createFolder`/`createSubfolder` allowed 200-char names, `renameFolder` enforced 100. Same field, different rules across stories. Caught and fixed in review but caused by specs written independently without cross-checking.
- **Dead code built then removed in review** — Both stories implemented server queries that duplicated client-side data: `getFolderAncestors` (2.1) and `getFolderDescendantCounts` wiring (2.2). Both removed when review identified the `allFolders` data was sufficient.
- **Interaction-level bugs only caught in review** — Blur/Enter race condition on rename input, `isRenaming`/`isDeleting` guards for duplicate mutations. Component tests only assert DOM presence, not user interaction flows.
- **Deferred work accumulating** — Items from Story 1.1 (`/api/rag/*` auth, SSR hydration) still unaddressed. `window.prompt()` flagged in 2.2 review as pre-existing from 2.1. Parallel items without story assignment drifted.

---

## Key Insights

1. **Prep work pays for itself** — All 4 critical items from Epic 1's retro directly enabled Epic 2 velocity. Parallel items without story assignment drifted indefinitely.
2. **"Do I already have this data?" before building new queries** — Both stories built server queries duplicating client-side data from `allFolders`. Review caught it, but asking earlier saves the build-then-remove cycle.
3. **Emit wiring is a two-file contract** — The dev implementing the emit owns wiring both ends (child emit + parent handler) in the same PR.
4. **Component tests need interaction coverage, not just DOM presence** — DOM assertions miss race conditions, duplicate mutations, and event handling gaps.
