## Challenges

- **Fragile ConvexClient access** — `convex-auth.client.ts` uses `Object.getOwnPropertySymbols` to reach the raw client because `nuxt-convex` doesn't expose a typed plugin API. Works but brittle.
- **JWKS bootstrap is manual** — New contributors cannot reach working Convex auth without undocumented manual key export step. Onboarding blocker.
- **Component test infrastructure not runnable** — 58 `it.skip()` test stubs exist but `@nuxt/test-utils` and `happy-dom` are not installed; vitest config excludes `tests/component/**`. Tests are dead code until fixed.
- **Data model gaps visible to users** — `documentCount` always shows 0 (no increment mechanism until Epic 3), `lastActivity` shows `_creationTime` instead of actual activity (no `updatedAt` field).
- **SSR hydration mismatch on dashboard** — Server renders loading skeletons, client immediately switches state after Convex subscription fires.

---

## Key Insights

1. **Code review process is working** — Keep the current discipline of documenting findings, resolving what's actionable, and explicitly deferring the rest with rationale.
2. **Test stubs without runnable infrastructure create false confidence** — 58 stubs look like coverage but aren't executable. Fix tooling before accumulating more stubs.
3. **Data model decisions in early epics have visible downstream effects** — Fields like `updatedAt` and `lastActivity` should be considered upfront even when the UI doesn't need them yet.
4. **Leverage existing UI primitives over building from scratch** — Reka UI Tree component provides accessible tree with keyboard nav and ARIA attributes, avoiding a complex custom build for Epic 2.
