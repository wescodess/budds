## Successes

1. **Prep sprint discipline worked.** All 7 carried/new action items from Epics 1-2 were completed before Epic 3 started. The mandatory gate prevented tech debt from accumulating further. Total: 6 prep stories, 5 PRs.

2. **Multi-engine orchestration held up.** Story 3-1's parallel dispatch pattern (text + quiz + flashcard + audio) with graceful partial failure proved resilient. When audio generation was added in 3-5, it slotted in cleanly — just one more promise in `Promise.all`.

3. **entityType resolved the deletion inefficiency.** The 3x try/catch entity lookup from Epic 2 was eliminated by storing `entityType` alongside `entityId` in contentBlocks (implemented in 3-1, retro action item #1). Direct lookup now possible.

4. **Component composition across stories was clean.** SectionBlockRenderer (3-3) dispatches to TextBlock, QuizBlock, FlashcardBlock, AudioBlock — each independently testable. AudioBlock started as a stub in 3-3, replaced with real implementation in 3-5. No refactoring needed.

5. **Code review caught real bugs in every story.** 9 blockers fixed across 5 stories: folderId! assertion for web-only courses (3-1), userId guard in triggerPreFetch (3-2), XSS in v-html markdown (3-3), threshold mismatch at score=90 (3-4), orphan blob cleanup on audio failure (3-5). Adversarial review continues to prove its value.

## Challenges

1. **Deferred items grew significantly.** 20 items deferred across 5 stories (vs 6 in Epic 2). Most are low-severity (timer leaks, over-fetching, missing aria-live) but the volume suggests the scope per story is at the edge of what's tractable in a single pass.

2. **Story runner didn't always complete the full pipeline.** Story 3-1's runner stopped at implementation without committing or creating a PR — the orchestrator had to handle the code review, fix a blocker, commit, push, and merge manually. This added friction.

3. **Test infrastructure gap persists.** 15 skipped component tests (from prep-3-5) remain unaddressed. Page-level tests with `provideFolderPageContext` requiring 15+ composable mocks are still not tractable. These need isolated component test rewrites.

4. **FR16 format override not implemented.** AC #6 of story 3-4 (user can override AI content format for next section) was scoped out. The adaptive hints flow through task metadata but no UI exists. This is a functional gap.

5. **Audio primers are conceptual-only.** Audio generation only fires for `knowledgeType === 'conceptual'`. Factual, procedural, and mixed sections get no audio. This is by design (from `getEngineConfig`) but limits the learning experience.

## Key Insights

1. **Prep sprint → epic flow is the right pattern.** Carrying tech debt without a blocking gate proved ineffective in Epics 1-2 (0/5 items addressed). Making the prep sprint mandatory resolved all items. Continue this pattern.

2. **Adversarial code review catches ~2 blockers per story on average.** Across Epics 1-3, code review has caught 13+ blockers. The pattern of XSS, missing guards, and threshold mismatches suggests these are systematic — not random. Consider a pre-review checklist for common issues.

3. **Graceful degradation is the right default for AI pipelines.** The section generation pipeline's partial-failure model (some engines fail, others succeed, user sees what's available) is more robust than all-or-nothing. Apply to future AI integrations.

4. **Schema-first design pays off.** Adding `entityType` and `failureNotice` to the schema in 3-1 made 3-3 (rendering), 3-4 (completion), and 3-5 (audio) straightforward — they consumed the schema rather than working around it.
