## What Went Well

- **Fifth consecutive 100% epic completion** — the process now holds across Epics 1–5 spanning auth, layout, folders, documents, RAG chat, and privacy. No epic has stalled, slipped, or required descoping.
- **All 5 Epic 4 prep items addressed or in flight before/during their consuming stories** — P0 #1 (cascade-delete audit) and P0 #2 (idempotent retryable AI Search delete path) both landed inside Story 5.1. P1 #3 (data-export package format spike) was executed inside Story 5.3. Only P1 #4 (Reka-portal `mountSuspended`) and P1 #5 (unify `/app/chat`) remain.
- **The `pendingCleanup` queue pattern was reusable on first try** — introduced in 5.1 for the account-cascade path, extended into 5.2 via a single extracted `enqueueDocumentCleanup` helper, and consumed with zero schema changes. Three callers now share identical enqueue logic with no divergence.
- **A latent Epic 2-era bug was discovered and fixed in passing** — `folders.deleteFolder` had returned `deletedDocuments: 0` since before documents existed as a table. Once 5.2 audited the cascade path, the bug surfaced and shipped its fix alongside the AI-Search gap closure in the same story.
- **A Story 3.3 deferred item was resolved with clean audit-trail mechanics** — the original bullet in `deferred-work.md` was struck through and annotated with the resolving-story pointer. Consistent with the file's "Resolved during…" convention.
- **NFR13 (24-hour external-data removal) has a measurable proof** — `30_000 * 2^10` capped at `3_600_000` gives a ~10-hour worst-case retry window per cleanup row, well inside the 24h NFR even under severe external-service outages. The cap is a test-asserted invariant, not a constant-to-trust.
- **Security model held without ceremony** — every new Convex query and mutation derives `userId` from `ctx.auth.getUserIdentity().tokenIdentifier`. The export path explicitly rejects any caller-supplied `userId`. No new endpoints were added beyond `GET /api/export/me`, and that single endpoint runs two auth guards (Nitro token + Convex identity).
- **Streaming zip chosen over JSON+signed-URL for export** — matches the AC's "contains original PDFs" literal requirement, avoids memory blow-up on 500-document accounts, and uses `fflate` (zero deps, ~30KB) over the heavier `archiver` alternative.
- **Epic closed on-time with no session handoffs** — all three stories plus three PRs merged to `dev` within a single orchestrator run (4 stories completed this run counting 4.4 → done from prior session).

## Challenges

- **Reka-portal component-test gap is now on its fifth story** — 4.3 (model-selector follow-ups), 4.4 (sidebar + new-chat), 5.1 (delete-account-dialog) have now shipped skipped component tests for portaled dropdown content. The Convex integration tests cover correctness, but component interaction coverage is a real and growing gap. Prep item #4 from Epic 4 retro (Elena) remains unresolved and is officially overdue.
- **One mid-session destructive `git checkout` in 5.3** — the runner ran `git stash && git checkout dev -- convex/ server/ app/ package.json pnpm-lock.yaml` to compare a test failure against `dev`, which overwrote the working tree. Recovered via `git stash pop` with no data loss, but the near-miss is logged in the 5.3 Decisions section and escalates `CLAUDE.md` guidance for any story-runner self-diagnostic ever using `git checkout -- <paths>`. Carried forward as a risk to address in runner policy, not the story itself.
- **No `pnpm lint` or `pnpm typecheck` scripts exist** — `pnpm test` is today's authoritative gate. The story-runner has no way to run a lint/typecheck pipeline without inventing one, which reduces drift-detection. Not a functional gap but a CI-readiness gap.
- **Documentation baseline of 8 pre-existing `convex/documentActions.test.ts` failures was carried through the entire epic without being investigated** — these were already present in Story 4.4's debug log and continued as background noise through 5.1 → 5.2 → 5.3. Every story's debug log asserts parity, but no one has fixed them. This is a creeping silence.
- **The export path is unbounded at the Convex layer** — `collectUserData` issues full-table scans per user-scoped table. Convex caps single-query reads at 16,384 documents. Realistic V1 users are far below that, but an extreme outlier (5k+ messages) would hit the cap. Deferred with a clear "paginate when > 5k messages per user" trigger.
- **Governing-law jurisdiction in `/terms` is a placeholder** — by design (tier-3 legal decision escalated per orchestrator policy), but it is a **blocker for GA**. The deferred item is tagged for the human owner before public launch.
- **No rate limit on `GET /api/export/me`** — an authenticated user could loop exports, causing repeated Convex scans + R2 fetches + zip assembly. Acceptable for private beta; a pre-GA gate.

## Key Insights

1. **Durable queue > inline retry** — the `pendingCleanup` table paid for itself across two stories. The pattern of "mutation enqueues rows, internal action drains with exponential backoff, reschedule is self-directing" is now the template for any future external-system side-effect that must honor an NFR time bound.
2. **Extract the helper the moment the second caller appears** — `enqueueDocumentCleanup` was extracted at the second caller (5.2's `documents.deleteDocument`) rather than the third. Delay would have risked the "parallel retry mechanism" failure mode that the story prompt explicitly flagged.
3. **Prep-item discipline still holds** — when retro prep items have named owners and P0/P1 tags, they get pulled into the first story that needs them. Fifth epic validating this.
4. **Latent cross-epic bugs surface when new cascades audit old cascades** — 5.2's work on `folders.deleteFolder` exposed the Epic-2 `deletedDocuments: 0` bug. Expect more of these as Epic 6 (quizzes) and Epic 7 (flashcards) introduce cascade paths touching Epic 3's documents.
5. **Skipped-tests debt compounds silently** — shipping `.skip` once was pragmatic; shipping it across five stories without a single attempt to un-skip is technical debt accruing interest. Un-skipping needs to be scheduled, not "eventually resolved."
6. **The 8-failure `documentActions.test.ts` baseline needs a decision** — it has now been the gate-parity baseline for four stories. Either fix, delete, or skip explicitly. A quiet known-red is worse than either an explicit skip or a green.
7. **Non-destructive download UX is cleaner without confirmation** — Export gets a spinner + toast, matching `useChat`-style async UX. Destructive actions (Delete Account) get `AlertDialog` + typed confirmation. The split cleanly reinforces the rule: confirm only what is irreversible.
8. **`GET` over `POST` for authenticated-only downloads is fine** — because the endpoint requires the Convex token and exposes only the caller's own data, CSRF is not in scope. `GET` lets the browser anchor-click download just work.
