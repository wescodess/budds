## Challenges

- **No new architectural challenges** — but this is itself a soft signal. Epic 6 leaned heavily on Epic 4 (RAG) + Epic 5 (cascade + export) plumbing without exercising new external systems. Epic 7 (Flashcards) likely repeats this pattern; the test of the pattern arrives when something post-MVP introduces a genuinely new external dependency.
- **`chat-input.test.ts` 6-failure baseline still pending** — Story 6-1 surfaced it; no story has been scoped to fix or `.skip` it. Mirrors the `documentActions.test.ts` problem at the start of Epic 5: a known-red baseline with no owner and no scheduled cleanup.
- **No `pnpm lint` / `pnpm typecheck` scripts** — carried from Epic 5 retro prep #4. Story-runner verdicts continue to set `lint_pass: null` / `typecheck_pass: null`. Not blocking, but the gate-pipeline gap persists.
- **Per-quiz `deleteQuiz` and account-wide cascade share invariants but not code** — 6-3's deleteQuiz uses `by_quizId` (narrow); accountDeletion uses `by_userId` (broad). Both honor child-before-parent. The Epic 5 retro rule was "extract at the second caller, not the third" — this is the second caller, so the rule says extract. Decision was deliberately deferred ("extract at the third caller") because the index dimensions differ enough that a shared helper would over-parameterize. Worth revisiting if Epic 7's flashcards introduce a third per-set delete path.
- **Attempts are point-in-time snapshots** (6-3 design decision) — editing a question's `correctAnswer` does **not** retroactively rescore prior attempts. Intentional V1.1 simplification but a real "user might be confused" risk. No telemetry yet to detect that confusion. Carried as a watch-item, not deferred work.
- **Free-response scoring is exact-match-after-normalization** (6-2) — case + whitespace insensitive, no semantic match, no partial credit. V1.1-acceptable, but quiz quality will be perceived as "strict" by users. Not a defect; a product call.

## Key Insights

1. **Component extraction is a portal-test escape hatch** — when a component can't be mounted via `mountSuspended` because of upstream portals, the answer is "extract it into a child component that has no portals" rather than "find a way to mount the portal". 6-1 proved this on the page level (QuizTab); 6-3 used the same technique on the menu/confirm pattern (inline swap, no DropdownMenu / AlertDialog).
2. **Index-tracked correctness beats text-tracked correctness** (6-3) — when a user can edit MC option text, binding `correctOptionIndex` instead of `correctAnswer === "ATP"` keeps the binding stable across renames. Generalizes: any "selected option" UI in an editable list should track by index in the draft and resolve to value on commit.
3. **Cascade re-audit is now reflexive, not procedural** — three new tables this epic, three child-before-parent insertions, all caught in the right place. The Epic 5 team agreement no longer needs the runner to remember it; it has become part of how the codebase is read.
4. **The "extract at second caller" rule needs index-shape qualification** — 6-3 had a second caller for cascade-delete logic but rejected extraction because the indexes differed. The rule should be stated as "extract at the second caller when the call shape is identical" — index dimensions count as part of the shape.
5. **Retro prep items shipped as story ACs achieve a higher completion rate than retro prep items shipped as standalone tasks** — Epic 5 retro #2 (prompt spike), #3 (Reka portal), #5 (test triage), #6 (cascade audit) were folded into 6-1's ACs and all closed. Compare to Epic 4 prep items #4 (Reka portal) and #5 (`/app/chat` unification), which were named-but-unscoped and drifted across epics. **Definition-of-Done discipline is the difference between "done in the next epic" and "still on the list".**
6. **Zero deferred items across an epic is possible when prep items are real ACs** — 0/0/0 across 6-1/6-2/6-3 is not a coincidence; it's the consequence of #5 above plus the runner having permission to refuse silent scope expansion (chat-input baseline got logged, not fixed).
7. **Schema migrations chain cleanly when the migration is "add table, add cascade, add export"** — schemaVersion went 1 → 2 (6-1 added quizzes + quizQuestions) → 3 (6-2 added quizAttempts). Each migration: schema edit + accountDeletion insertion + dataExport addition + manifest bump + integration test. No migration in this epic touched user data.
8. **In-tab everything beats route-based everything** for surfaces that share a parent context — quiz Tab hosts `QuizCardPreview`, `Taker`, and `Editor` as mutually-exclusive panels off `{ activeQuizId, editingQuizId }` refs. No route changes, no breadcrumb friction, no SSR hydration mismatch on auth-protected pages. Keep this for Epic 7's flashcards.
