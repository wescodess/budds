## Successes

1. **External API integration was well-contained.** All Google Calendar API calls are isolated in `server/utils/google-calendar.ts` and `server/utils/calendar-tokens.ts`. The Convex layer manages data; the server layer manages HTTP. Clean separation.

2. **Session composition as pure functions.** `determineSessionType` and `findNextPreferredSlot` in `server/utils/session-composition.ts` are independently testable (17 unit tests). Continues the pure function extraction pattern from Epics 4-5.

3. **Input validation caught early.** Story 6-2's code review found 3 input validation blockers (unconstrained sessionMinutes, invalid day strings, unvalidated time format). Fixed with Convex literal unions and regex validation before the data could flow into 6-3's scheduling logic.

4. **Cron-based rescheduling worked cleanly.** The hourly `checkMissedSessions` cron in `convex/crons.ts` uses the internal action pattern (query → process → mutate) without any external dependencies that could make it flaky.

5. **Dirty workspace handled gracefully.** Story 6-1 initially BLOCKED on a dirty workspace (27 uncommitted refactoring changes). The orchestrator escalated, user chose commit-all, and the retry succeeded. This validates the BLOCKED → escalate → retry flow.

## Challenges

1. **Deferred items continue to accumulate.** 15 new deferrals in Epic 6 — the highest for any epic. Many are duplication issues (`makeConvexClient` in 3 files, `GOOGLE_TOKEN_URL` in 2 files, `getTodayInTimezone` in 2 files, slot-finding duplicated across Convex/server boundary).

2. **Convex/server boundary forces code duplication.** The slot-finding algorithm had to be duplicated because Convex actions can't import from `server/utils/`. This is an architectural constraint. Consider a `convex/lib/` extraction for shared pure logic.

3. **1 regression introduced.** The calendar disconnect test (`CalendarConnectionCard > calls disconnect mutation on disconnect click`) broke because 6-5 changed the disconnect flow from direct Convex mutation to server endpoint. The test was not updated.

4. **Pre-existing contentFlags.test.ts failure persists.** First noticed during Epic 6 runs. Should be fixed in the next prep sprint.

5. **No error toasts pattern is accumulating.** Multiple stories defer error toast handling. This is now a systematic gap across the entire Learn module.

## Key Insights

1. **External API integrations need a clear server/Convex boundary.** Google Calendar calls must go through Nuxt server endpoints, not Convex actions (HTTP needed). The `ConvexHttpClient` pattern in server endpoints works but creates duplication (`makeConvexClient`). Extract to shared utility.

2. **Literal union validators are the strongest input validation.** Using `v.union(v.literal(5), v.literal(10), ...)` instead of `v.number()` prevents entire classes of input bugs. Apply to all enumerations going forward.

3. **Story runners sometimes skip story file creation.** Stories 5-5 and 6-1 had no story files — the runners didn't create them. Backfilled manually. Consider making story file creation a mandatory first step in the runner.
