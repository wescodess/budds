# Surface captures

Run `pnpm design:capture learn-adaptive-canvases` on demand. Install Chromium once with `pnpm exec playwright install chromium`. The route capture itself is on demand. `pnpm test:design-capture` runs the real CLI in Chromium against seeded self-contained HTML, without the E2E stack. It is excluded from `pnpm test` and runs in the CI browser journeys job after Chromium is installed. The suite includes the intentional 30-second unmet-readiness timeout; it proves axe, overflow, target size, fill separation, status tone, readiness, required fonts, failed requests, comparison exit codes, and SIGINT during publication.

Run route captures separately from Nuxt builds and component tests, which share generated Nuxt/Vite caches. A dependency-cache 504 is a capture error; rerun after compilation finishes.

Route captures also take a per-user machine lock in the OS temporary directory (`budds-design-capture-stack-<uid>.lock`) before starting the stack. A simultaneous route capture, including from another checkout or with an explicit frontend port, fails clearly and keeps error staging instead of publishing. The existing stack creates unique disposable worktrees and project-local Convex data directories, but Convex probes backend ports starting at 3210/3211 without reserving them and shares binary/dashboard caches across checkouts. Anonymous mode also uses the fixed deployment name `anonymous-agent` and can fall back to matching legacy state in the user’s home directory. Nuxt also shares generated caches within a checkout. This command therefore permits only one route stack at a time; standalone HTML needs no stack lock. The lock records an owner PID, start time, unique token, and stack process groups with each member's PID, process start time, command line, and group ID. The stack leader must identify `e2e-stack.mjs`. Capture opts into `BUDDS_E2E_OWNED_GROUPS_FILE`: `spawnOwnedChild` in `scripts/e2e-stack-runtime.mjs` synchronously appends each detached owner PID immediately after spawning it. If registration fails, it SIGKILLs the just-spawned group and rethrows the write error. The per-run JSONL file lives beside the lock, keyed by the owner token, preserving the single metadata file inside the lock directory. Readiness checks read registrations without enumerating the process table, inspect each new live owner PID once, and persist its identity in lock metadata. One initial ancestry snapshot supplements registration for children already present when the stack is recorded; stale metadata is only inspected for surviving groups. Registrations remain discoverable even if the stack exits before the next readiness check. Cleanup holds the lock until the stack group and every recorded detached backend group have stopped. After the stack's shutdown grace period, remaining groups get another 30 seconds to finish, then SIGTERM with a 30-second grace period and finally SIGKILL with a two-second disappearance check. Every signal requires a matching recorded process identity; recorded surviving members can verify a group after its leader exits. A transient `EPERM` during group shutdown is accepted only if a later probe confirms that the group is gone. A later run atomically replaces an empty legacy lock or claims a dead owner by renaming that exact owner's uniquely named metadata file to its own live PID/token. Only one stale-lock contender can win that rename. Stale recovery never signals processes. Before claiming a dead owner's lock, it checks recorded identities and every registration, including entries not yet in metadata. A matching recorded group, any live registered PID or group (even if its identity differs), or an inspection failure refuses recovery. The error lists the affected PIDs/PGIDs and lock path: inspect each group with `ps -o pid,pgid,lstart,command -g <pgid>`, stop the processes, then remove the specified lock directory and retry. A reused recorded leader with a different identity can be left untouched only when it has no live registration. When all previous groups are confirmed gone, the existing atomic takeover proceeds. Cleanup rereads registrations after the stack and known groups stop, so a spawn during cleanup also retains the lock. Registration files are removed only after cleanup confirms their groups have stopped or their leader identities prove PID reuse. A registered live PID without a captured, verifiable identity retains the lock and requires manual recovery. The lock stays held if any group cannot be verified or confirmed stopped. A live owner still blocks capture; unrelated process groups are never eligible for cleanup. Other E2E commands do not participate in this lock and should be run separately. `e2e-stack.mjs` is unchanged; the runtime registration hook is opt-in and performs no registration writes when the variable is unset, preserving other E2E commands. A stack exit before readiness (even during a successful HTTP probe) fails through `stackFailure`; failed runs never publish. The stack gets 300 seconds to become ready, matching Playwright's web server timeout, because it builds Nuxt before listening.

Definitions live in `docs/design/surfaces/<surface>.json`. Version 1 requires:

- `kind`: `routes` starts the existing disposable `scripts/e2e-stack.mjs`. Each case has a local `path`. Without `BUDDS_E2E_BASE_URL`, the OS selects a free IPv4 loopback port with `listen(0)`; there is no default shared port. An explicit HTTP loopback URL preserves occupied-port rejection, but coordinating that port between callers is the caller’s responsibility: the probe releases it before startup. The runner never deliberately reuses a server. Existing production, loopback, and disposable-deployment checks still apply.
- `kind`: `html` opens `file` directly (absolute or relative to the repository root), starts no stack, and blocks HTTP requests. Keep mockups self-contained with inline CSS, scripts, images, and fonts. Each case identifies the static content; use separate definitions for different HTML files.
- `notes`: why these cases represent the surface and what is omitted.
- `themes`: `dark` and/or `light`. Each isolated browser context sets its color scheme, root class, and `budds-color-mode` before the page boots. HTML concepts can use those classes or `prefers-color-scheme`.
- `viewports`: CSS-pixel `{ "width": 320, "height": 640 }` objects.
- `cases`: unique `{ "kind": "concept", "state": "ready" }` identities, plus `path` for routes.
- `readySelector`: a visible readiness marker, ideally including a hydration/state attribute. Select a marker specific to the expected content so a loading spinner or error cannot satisfy it.
- `contentSelector`: exactly one visible, nonempty main content element to crop.
- Optional `requiredFonts`: font families that must actually load. All declared font failures, page errors, failed requests, HTTP errors, and unexpected redirects fail capture.
- Optional `surfaceSeparation`: `{ "selectors": ["#bubble", "#canvas"], "minContrast": 1.1 }` pairs. Each selector must match one visible element. The check composites computed background fills through their ancestors in sRGB, then compares relative luminance. Gradients, images, opacity, filters, and blending fail the check as unsupported instead of silently passing. This is a project-specific fill check, not a WCAG text contrast threshold.

Minimal HTML definition:

```json
{
  "version": 1,
  "kind": "html",
  "file": "/tmp/concept.html",
  "notes": "Pre-approval static concept; no server or learner data.",
  "themes": ["dark", "light"],
  "viewports": [{ "width": 320, "height": 640 }],
  "readySelector": "main[data-ready=true]",
  "contentSelector": "main",
  "cases": [{ "kind": "concept", "state": "ready" }]
}
```

Successful output goes to gitignored `.design-captures/<surface>/<short-sha>/`. Each run first writes to a unique sibling `<short-sha>.staging-<unique-suffix>/`, leaving the published capture intact. Only a complete run publishes: a short per-SHA lock serializes renames of the previous folder to a unique backup and staging to the published path, then removes the backup. There can be a brief gap between the two renames; concurrent runs never combine files. A failed run or an interrupt before the atomic publication rename exits 1, prints its staging path, and retains error `floor.json` and `manifest.json` reports there for inspection. Publication checks cancellation while waiting for its lock and immediately before the synchronous rename transaction. If interruption arrives after the atomic rename, the complete published result stands; the CLI says so and reports that committed result. You can delete that staging folder. A hard kill also leaves staging with its initial error report. Staging, temporary backups, and publication locks are not published captures and cannot be used with `--compare`, even if their report says complete. A stale `<short-sha>.publish-lock/` after a hard kill can be deleted once no run is publishing. All output folders must be direct children of the surface folder; symlink traversal is refused. To preserve a baseline's images, copy it to another gitignored folder such as `.design-captures/<surface>/baseline-<name>/`; never commit captures, because the repository is public; same-directory comparison reads its complete `floor.json` before capturing. `manifest.json` records the full SHA, dirty-worktree flag, definition, runtime, capture status, rendering/font metadata, and each full-frame `file` and `cropFile`. Frames include the full page; content crops preserve 1 CSS pixel per image pixel at DPR 1 with no resizing. Captures wait for readiness, fonts, network quiet, and two animation frames with motion disabled.

`floor.json` records every completed capture identity and axe WCAG A/AA findings (including WCAG 2.2 target spacing), horizontal overflow at every viewport, a stricter 24×24 CSS-pixel target floor, and configured fill separation. The stricter size floor deliberately reports undersized controls even when WCAG spacing or inline exceptions might apply; it is not a conformance verdict. For clipped or 1px native inputs, it measures a visible associated label as the activation target. Visually hidden form transport inputs with `aria-hidden="true"` or negative `tabindex` are skipped because they are not activation targets. Other hidden inputs without a visible label remain findings; reports retain both input and measured target selectors. Axe checks requiring manual review are retained in `incomplete`. Existing product debt is reported without changing product code.

`status-tone` enforces the [state color rule](../../../DESIGN.md#functional-colors). For each visible `role="status"` or `role="alert"` region, it checks the first visible SVG, falling back to an `animate-spin` element. Icon candidates must have a client rect with positive width and height. If neither exists inside the region, it also accepts an immediately preceding decorative (`aria-hidden="true"`) SVG or spinner when that parent has exactly two visible element children: the icon and the status. Straight back state 12 uses this pairing; a descendant-only scan misses its Not yet icon. Larger containers and unrelated sibling content are not searched. It compares computed `color` with the region's inherited `--foreground` and `--muted-foreground` tokens at the icon, resolving CSS colors to sRGB pixels so equivalent hex, RGB and OKLCH values compare equally. A neutral icon produces one finding against the status region's stable selector. Button descendants (including `role="button"`) are excluded, even when a status wraps the button. Genuine neutral metadata opts out with `data-tone="neutral"` on the status or an ancestor. Text-only regions and documents without these tokens are outside this check. This detects neutral replacement, not whether a colored icon uses the correct state hue; it assumes icons paint with `currentColor` as Lucide does. It adds no rule to the source ratchet.

Record existing app debt with the same capture baseline mechanism: capture once with this check enabled, copy the complete output to `.design-captures/<surface>/baseline-status-tone/`, then run `pnpm design:capture <surface> --compare .design-captures/<surface>/baseline-status-tone`. The baseline retains every finding and capture identity; unchanged debt passes and any new finding fails. Keep these reports local and gitignored, and report counts in the PR. Do not add rendered findings to `docs/design/ratchet-baseline.json` or exempt meaningful states with `data-tone="neutral"` to hide debt.

Without comparison, violations exit 0. `--compare <capture-dir>` exits 1 for IDs absent from that baseline's `floor.json` and for any baseline capture identity missing from the current run, naming its case, theme, and viewport. Added coverage is allowed; its findings count as new. Older baselines without capture identities must be recaptured. IDs hash the rule, surface/kind/state/theme/viewport, and selector, excluding SHA and measured values. Custom layout checks prefer a unique `data-testid` to an ID. Before hashing custom selectors and axe targets, Vue/Reka generated ID counters (`v-0`, `v-0-1`, `reka-v-0`, `reka-1`) are normalized. Within each capture, repeated matches for the same rule and normalized selector add an occurrence ordinal in report order to the second and later hashes; the first keeps its existing ID, and raw selectors stay in the report. Authored IDs and positional selectors remain distinct. An unrelated sibling insertion can change positional IDs and needs human triage. Self-comparison is supported because the baseline is read before output is written. Errors always exit 1 and mark both reports `error`; incomplete or failed baselines are rejected. The stack runs in its own process group. The CLI owns browser signal handling. Ctrl+C and termination forward SIGTERM to the verified stack group, wait up to 120 seconds (Playwright's stack shutdown grace) for asynchronous stack cleanup, then force any verified survivors in that group. Cleanup also waits for the recorded detached backend groups before releasing the lock, using the escalation described above; normal completion uses the same cleanup. Automated findings and viewable synthetic renders do not constitute human design approval.
