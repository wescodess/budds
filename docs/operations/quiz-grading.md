# Quiz grading

`QUIZ_GRADING_MODE` belongs on the **Convex deployment**. It defaults off: only the exact value `graded` enables rubric grading for newly submitted free-response and fill-in-the-blank answers. Activation is an owner decision. This change sets no environment variables and performs no deployment.

The action reuses the existing Cloudflare AI Gateway and OpenRouter credentials from Convex environment configuration. Nuxt runtime configuration and the learner's generation-model selection do not configure the grader. The fixed policy requests `xingchen-agi/xing4.0-29b-a4b:free` from Phala, caps prompt and completion prices at zero, requires ZDR and no data collection, disables provider fallbacks and payload logging, and skips the gateway cache. The route fails closed when unavailable; it never selects a paid alternative.

All three attempt-completion paths schedule an internal mutation that atomically claims pending rubric answers, establishes lease recovery and schedules a separate dispatch action. The action arguments contain only IDs, claim IDs and digests; the dispatch transaction revalidates ownership, parents and canonical inputs before returning stored bodies to the action. Batches contain at most eight answers and fit the complete serialized 96,000-byte UTF-8 request, including nested JSON escaping, response schema and provider fields. Exact matches and empty answers finish deterministically. Each provider batch has a two-minute lease and a separately scheduled recovery mutation. Requests time out after 30 seconds. Timeouts, 429 responses and server failures back off the entire attempt, including untried rows, for three attempts per retry cycle; a 429 also establishes a shared provider cooldown across attempts and learners; `Retry-After` is capped at 15 minutes. Exhausted or malformed results become unavailable and earn no credit, remaining in the denominator. Provider failures never create an incorrect verdict. The learner can manually retry unavailable answers twice per row or self-assess them instead. A manual cycle is charged at its first actual dispatch reservation; unavailable capacity does not consume a cycle. Individually unfit inputs remain unavailable for self-assessment and are excluded from futile manual retries.

Convex validates every answer and criterion key and computes fractional points from the stored weights. Met criteria count even when another criterion is uncertain. Self-assessment replaces the credit with 1, 0.5 or 0 and retains the model's criterion results. Only the latest completed attempt can update the quiz's displayed score. Criteria, weights and verdicts stay internal; results expose points, plain feedback, the grade source and the answer ID for self-assessment.

## Rollback

Turn the Convex flag off to stop creating new rubric work. Assessments retain their mode through `rubricVersion`, so already-created rubric rows continue through completion, recovery and bounded manual retries even after the flag changes. Historical advisory rows and attempts without rubric rows are not rewritten. The existing Laya and shadow paths continue to ignore rubric rows.

Keep the additive schema fields/indexes and the grading functions deployed until existing pending rows have drained. Reverting only the dispatch/commit implementation with work in flight would remove lease recovery. Turning the flag off does not reverse already-recorded grades or self-assessments; reversing those requires a separate, reviewed data operation.

## Validation boundary

Local tests use a mocked gateway and synthetic answers. They establish request construction, key validation, score arithmetic, retry limits, leases and deletion fencing. These checks do not establish live provider availability, grading quality, injection resistance or upstream retention behavior. Production release requires the repository checks and review gate at the final release commit.

## 2026-11-05: bounded inputs, admission and prompt revision

Canonical grader evidence is limited to 1,200 Unicode code points before hashing and dispatch. New rubric snapshots use that bound. Older accepted snapshots remain unchanged; the grader derives a bounded canonical excerpt from them. Learner text and reference answers are preserved in full. If one complete item cannot fit the request cap, only that row receives the existing internal `oversized_evidence` unavailable reason (an input-size outcome, including oversized answers or references); it receives no incorrect verdict and cannot poison other rows.

Convex admits at most three new attempts requiring model work per learner in each 60-second admission window. At dispatch reservation it atomically enforces 25 dispatches per learner and 50 shared dispatches per UTC day. These are application caps, not claims about upstream quota. Exact, empty and other deterministic answers consume neither admission nor dispatch budget. Refusals stay unavailable and support self-assessment or a later bounded retry after capacity returns. Protected internal keys reuse `rateLimitBuckets`; shared counters and cooldowns contain no learner identity or bodies. Per-learner counters follow account deletion, and all counters expire through ordinary cleanup. A missing or foreign folder fences enabled/stored rubric acceptance, dispatch, retry, self-assessment and late commits, alongside the existing account, quiz and course fences. The folder deletion cascade and document retention policy are unchanged.

The current prompt is `quiz-rubric-judge.v2`. Ordinary omissions, irrelevance and explicitly wrong content are `not_met`. `uncertain` is reserved for a substantive answer or evidence that is genuinely ambiguous, conflicting or cannot be judged. Credit arithmetic is unchanged: met ideas still count, and a learner decision replaces credit with 0, 0.5 or 1. Offline fixture expectations now follow this policy and retain the genuinely ambiguous gas-exchange example. Feedback containing internal criterion keys or verdict codes uses the neutral fallback sentence.

The earlier credentialed smoke observations describe historical v1 behavior. Subsequent live DEV browser checks exercised v2 and accepted natural paraphrases and one-character typos. An earlier live DEV run also awarded full credit to an unrelated answer; that false-credit result is tracked in [#374](https://github.com/wescodess/budds/issues/374). The full revised fixture set has not been validated live, and broad grading quality and injection resistance remain unproven. Offline regression tests and script guards establish implementation behavior only. Activation remains off by default and is controlled on Convex after release.
