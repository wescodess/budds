# Quiz grading

`QUIZ_GRADING_MODE` belongs on the **Convex deployment**. It defaults off: only the exact value `graded` enables rubric grading for newly submitted free-response and fill-in-the-blank answers. Activation is an owner decision. This change sets no environment variables and performs no deployment.

`QUIZ_GRADING_PROVIDER` is a server-only **Convex** selector. Unset or exactly `openrouter` retains the existing Cloudflare AI Gateway/OpenRouter route: `xingchen-agi/xing4.0-29b-a4b:free` from Phala, zero prompt/completion maximum prices, required ZDR, denied data collection, disabled provider fallbacks and payload logging, and skipped gateway cache. Exactly `groq` opts into the fixed route below. Empty, misspelled or unknown selectors fail closed. There is no arbitrary model setting or automatic switch between routes. Nuxt public configuration and the learner's generation-model selection do not configure the grader.

All three attempt-completion paths schedule an internal mutation that atomically claims pending rubric answers, establishes lease recovery and schedules a separate dispatch action. The action arguments contain only IDs, claim IDs and digests; the dispatch transaction revalidates ownership, parents and canonical inputs before returning stored bodies to the action. OpenRouter batches retain their eight-answer, 96,000-byte complete UTF-8 request limit, including nested JSON escaping, schema and provider fields. Groq uses its smaller limits below. Worker selection, transport and manual retry eligibility use the same selected route's serialized request bounds. Answers and references are never silently truncated; an individually unfit row cannot poison normal rows. Exact matches and empty answers finish deterministically.

Each provider batch has a two-minute lease and separately scheduled recovery. Requests time out after 30 seconds. Three actual dispatch reservations are allowed per automatic cycle; undispatched claim recovery, pacing and cooldown waits consume no attempt, provider dispatch or manual cycle. Timeouts, 429 responses and server failures back off the whole attempt, including untried rows. A 429 also establishes a shared cooldown for its actual provider across attempts and learners. Valid `Retry-After` floors are never shortened: delays beyond the 15-minute automatic retry window settle affected pending rows unavailable, release leases and retain a durable not-before gate for later manual retry. There is no automatic provider request at a long floor. Exhausted or malformed results remain unavailable and earn no credit, remaining in the denominator; provider failures never create an incorrect verdict. The learner can manually retry unavailable answers twice per row or self-assess them. A manual cycle is charged at its first actual dispatch reservation. Individually unfit inputs remain unavailable for self-assessment and are excluded from futile manual retries under the selected route's limits.

Convex validates every answer and criterion key and computes fractional points from the stored weights. Met criteria count even when another criterion is uncertain. Self-assessment replaces the credit with 1, 0.5 or 0 and retains the model's criterion results. Only the latest completed attempt can update the quiz's displayed score. Criteria, weights and verdicts stay internal; results expose points, plain feedback, the grade source and the answer ID for self-assessment.

## Optional Groq Free route

Before any learner content is sent, the owner must create a dedicated Groq credential, verify that its organization is on the **Free plan, has never been upgraded or paid**, and enable ZDR for synchronous inference in that organization. Publish the Groq processor disclosure on the public privacy page before activation. A dedicated organization is recommended so other workloads do not consume its quota. Do not upgrade it or attach a paid fallback. Groq has no per-request zero-price enforcement field: zero billing depends on the provider-enforced Free account plan. These configuration confirmations are owner attestations, **not external verification** of billing, ZDR or credential validity. If account status or retention settings change or become uncertain, remove the confirmations before further inference.

Set these private values only on the authorized Convex deployment, after the prerequisites and release review:

| Variable | Required value |
| --- | --- |
| `QUIZ_GRADING_PROVIDER` | `groq` |
| `QUIZ_GRADING_GROQ_API_KEY` | Dedicated server-only credential |
| `QUIZ_GRADING_GROQ_FREE_PLAN_CONFIRMED` | Exactly `true`, after the Free account check |
| `QUIZ_GRADING_GROQ_ZDR_CONFIRMED` | Exactly `true`, after enabling ZDR |

A missing key or either missing/false confirmation prevents network dispatch and dispatch/manual budget consumption. The route calls only `https://api.groq.com/openai/v1/chat/completions`, synchronously, with `openai/gpt-oss-120b`, strict JSON schema, `reasoning_effort=low` and `include_reasoning=false`. GPT-OSS does not support `reasoning_format`; reasoning still runs but is excluded from the response. It makes one fetch per dispatch reservation, refuses redirects, and uses no SDK retries, tools, streaming, batches or persistence features. Responses are limited to 32,000 bytes. Alternate returned model identities, truncated completions and invalid IDs, criterion keys, verdicts or feedback fail unavailable. Server credit arithmetic is unchanged.

Groq batches contain at most two items and at most **6,000 bytes for the complete serialized UTF-8 body**, with `max_completion_tokens=1024`. Conservatively reserving one input token per wire byte leaves 976 tokens of framing headroom within an 8,000-token reservation. Shared atomic pacing allows one reservation per 61 seconds across all learners and attempts. Groq permits at most 24 dispatches across all learners and 12 per learner in any rolling 24 hours. Each reservation occupies an indexed slot until its own 24-hour expiry, so neither allowance refills at UTC midnight. That bounds shared reservations to 192,000 estimated tokens in any 24 hours. The common learner cap of 25 and OpenRouter's separate shared cap of 50 per UTC day also remain. These are conservative application bounds, not a provider tokenizer measurement or verified quota guarantee. The owner must check the actual organization's RPM, RPD, TPM, TPD and any separate input/output limits before activation; lower limits or other traffic may still produce 429s.

This is a limited-capacity free route, requiring owner acceptance before activation: at most 24–48 model-checked answers per rolling 24 hours across the app, and 12–24 per learner, depending on how many complete items fit a batch. A ten-answer quiz needs five to ten dispatches and takes roughly four to nine minutes after its first dispatch, before contention or retries. Larger inputs, including long multibyte excerpts, may not fit individually and remain available for self-assessment. A large quiz can exhaust a learner's allowance within one attempt. Exact and empty answers do not use this capacity. Retain the OpenRouter default if this capacity is insufficient; selecting Groq does not increase quota or establish production availability.

An eligible manual retry can queue during the 61-second pacing wait without consuming a manual cycle. The worker waits before dispatch. Actual upstream cooldowns, attempt/answer retry floors, admission refusals and exhausted budgets still prevent retries until eligible.

Canonical digests cover the actual serialized route/policy and an opaque configuration fingerprint. Selector, credential or confirmation changes fence stale claims and late grades; undispatched claims recover without consuming an attempt. Internal records retain the actual provider and model/policy revision from dispatch. Existing attempt not-before gates remain conservative across route changes. Changing a selector does not rewrite recorded grades or enable a fallback.

An implausibly long `Retry-After` keeps the route paused rather than sending early. Verify it against provider support and account limits before any owner-authorized reset. Recovery must inspect both the shared provider cooldown and retained attempt/answer not-before floors; deleting a shared bucket alone does not clear row floors. Do not shorten these automatically or retry while investigating. Any reset of stored floors is a separately reviewed data operation.

Production diagnostics use the fixed `Quiz grading unavailable` message and bounded provider/reason/limiter-source enums, a validated HTTP status and optional numeric not-before timestamp. `limiterSource=upstream` identifies an HTTP 429; `local` identifies application admission/daily capacity refusal. The precise upstream limiter subtype remains unknown. Upstream error bodies are not read, persisted or logged, including oversized and malformed error responses. No request bodies, raw headers, arbitrary provider messages, IDs, keys or learner content are logged. These diagnostics do not alter learner responses.

Primary contracts: [strict output support](https://console.groq.com/docs/structured-outputs), [chat request fields](https://console.groq.com/docs/api-reference), [GPT-OSS reasoning options](https://console.groq.com/docs/reasoning), [organization rate limits](https://console.groq.com/docs/rate-limits), [billing and upgrades](https://console.groq.com/docs/billing-faqs), and [data controls and ZDR](https://console.groq.com/docs/your-data). Published Free limits for this model list 30 RPM, 1,000 RPD, 8,000 TPM and 200,000 TPD; exact account limits may differ.

## Rollback

Turn the Convex flag off to stop creating new rubric work. Assessments retain their mode through `rubricVersion`, so already-created rubric rows continue through completion, recovery and bounded manual retries even after the flag changes. Historical advisory rows and attempts without rubric rows are not rewritten. The existing Laya and shadow paths continue to ignore rubric rows.

Keep the additive schema fields/indexes and the grading functions deployed until existing pending rows have drained. Reverting only the dispatch/commit implementation with work in flight would remove lease recovery. Turning the flag off does not reverse already-recorded grades or self-assessments; reversing those requires a separate, reviewed data operation.

## Validation boundary

Local tests use mocked fetch/gateway responses and synthetic answers. They establish request construction, configuration gates, key validation, wire bounds, score arithmetic, shared pacing, retry floors/limits, leases and deletion fencing. They do not establish live provider availability, grading quality, injection resistance, account billing status or upstream retention behavior. Groq documents strict JSON-schema support for this model but does not enumerate acceptance of every schema keyword used here; validate the exact wire schema before activation. Hiding reasoning does not disable it, and the 1,024-token completion allowance must be validated against real grading outputs, including truncation. Convex's documented direct `fetch(url, { redirect: 'error' })` and public runtime implementation reject redirects; this has not been re-tested on the hosted deployment. The pacing policy is a precaution, not a demonstrated fix for the earlier OpenRouter 429s. Production release requires the repository checks and review gate at the final release commit; credentials, account checks, capacity acceptance, deployment, activation and any separately authorized live validation remain owner tasks.

## 2026-11-05: bounded inputs, admission and prompt revision

Canonical grader evidence is limited to 1,200 Unicode code points before hashing and dispatch. New rubric snapshots use that bound. Older accepted snapshots remain unchanged; the grader derives a bounded canonical excerpt from them. Learner text and reference answers are preserved in full. If one complete item cannot fit the request cap, only that row receives the existing internal `oversized_evidence` unavailable reason (an input-size outcome, including oversized answers or references); it receives no incorrect verdict and cannot poison other rows.

Convex admits at most three new attempts requiring model work per learner in each 60-second admission window. At dispatch reservation it atomically enforces 25 dispatches per learner and 50 shared dispatches per UTC day. These are application caps, not claims about upstream quota. Exact, empty and other deterministic answers consume neither admission nor dispatch budget. Refusals stay unavailable and support self-assessment or a later bounded retry after capacity returns. Protected internal keys reuse `rateLimitBuckets`; shared counters and cooldowns contain no learner identity or bodies. Per-learner counters follow account deletion, and all counters expire through ordinary cleanup. A missing or foreign folder fences enabled/stored rubric acceptance, dispatch, retry, self-assessment and late commits, alongside the existing account, quiz and course fences. The folder deletion cascade and document retention policy are unchanged.

The current prompt is `quiz-rubric-judge.v2`. Ordinary omissions, irrelevance and explicitly wrong content are `not_met`. `uncertain` is reserved for a substantive answer or evidence that is genuinely ambiguous, conflicting or cannot be judged. Credit arithmetic is unchanged: met ideas still count, and a learner decision replaces credit with 0, 0.5 or 1. Offline fixture expectations now follow this policy and retain the genuinely ambiguous gas-exchange example. Feedback containing internal criterion keys or verdict codes uses the neutral fallback sentence.

The earlier credentialed smoke observations describe historical v1 behavior. Subsequent live DEV browser checks exercised v2 and accepted natural paraphrases and one-character typos. An earlier live DEV run also awarded full credit to an unrelated answer; that false-credit result is tracked in [#374](https://github.com/wescodess/budds/issues/374). The full revised fixture set has not been validated live, and broad grading quality and injection resistance remain unproven. Offline regression tests and script guards establish implementation behavior only. Activation remains off by default and is controlled on Convex after release.

The historical T5 smoke plan remains **halted at 5/8 requests**. No further provider requests are authorized under that plan. The manual runner requires an existing ledger and refuses to create a fresh request budget when both the local ledger and committed observations are absent.
