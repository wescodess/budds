# Measurement snapshot operations v1

C6.2 consumes report source v4 and produces report v3 aggregates using the v1 query and metric definitions. It adds no production principal, approved roster, grant, enrollment, flag, model call or baseline evidence. `LEARN_MEASUREMENT_CAPABILITIES.reports` remains false. The server-only approval catalogue in `learnV2MeasurementReportAccess.ts` is empty. Populating it or activating collection requires the separate owner authorization.

An approval binds the verified full application `tokenIdentifier`, binding/grant versions, cohort, epoch, baseline SHA, frozen protocol and replacement policy to an explicit owner roster. The frozen time must precede enrollment. Viewer grants are server-managed; no public provisioning or self-grant command exists. Public requests contain only an owned grant reference, command key, enrollment interval and cutoff. The service derives scope from the grant and approval and rejects arbitrary learner/stratum filters.

`requestReport` coalesces matching builds and saves command hashes in the private build manifest. Replay is scoped to the approved query/cutoff. A fresh command after completion or a later cutoff creates a new run. `beginReportSnapshot` supplies the same server-only command boundary. `dailyRefresh` uses the current cutoff and schedules its next daily invocation only after an authorized request succeeds; nothing starts that chain automatically. Revocation or disabled capability stops it. While a new run builds, `getReport` may return the last authorized completed run for that interval, with its own run ID, cutoff and extraction dates. Consumers must follow that returned ID; the service never labels the old data with the new cutoff.

`pinReportOwners` persists the sorted roster as source-owner watermark rows in batches of eight. The private control manifest also pins a digest of the complete approval. Source extraction traverses each owner's append-only sequence through that saved watermark, detects gaps, and selects the target epoch's admissions and Independent claims before joining any outcomes. It never reconstructs historical mastery from current projections. Missing captures normalize to unknown; missing or unscored outcomes remain null. Joins verify authoritative attempt/execution references, score and scorer identity pins, current permitted source evidence, and the original first-slot link. Protocol policy governs replacements; the original cold and delayed slots remain primary unless inclusion was predeclared.

Each extraction continuation reads at most four fact records and emits at most eight normalized records. Rows, page digest, byte/population counters, source cursor and next scheduled continuation commit together. Pages are capped at 256 KiB. Runs enforce a 90-day enrollment interval, 10,000 assignments/claims, and 64 MiB of source/normalized input. Ambiguous per-record history, conflicting duplicates, a stuck cursor, a missing page/fact or overflow fails incomplete. No reader silently truncates a population. Replaying a committed page verifies its digest and appends nothing.

`finalizeReport` reads and verifies every saved source-page manifest, reconciles the whole run, fingerprints the canonical normalized inputs and runs the shared computation in an action. C6.3/offline consumers must likewise run reconciliation, fingerprinting and the 10,000-replicate bootstrap in an action or offline at the 10,000-episode / 64-MiB maxima, never in a query or mutation. Output pages are saved idempotently; sealing checks the input digest, source and cell counts, build phase and current revocation. All cells share the computation's run-level legacy audit. Unknown audits remain unknown; fixtures establish no legacy or prospective learning claim.

This is a logical snapshot with a per-owner watermark vector and actual extraction interval, not a global atomic multi-transaction database image. Ordinary post-watermark writes cannot alter its frozen inputs. Later integrity facts, source invalidation or account tombstones immediately withhold cached output. On every direct manifest/page/export request, the service rechecks verified principal, active grant, approval scope and current deletion/integrity guards. The revocation query reserves a finite 3,000-range budget; exhausted validation returns `source_validation_incomplete` without aggregates. Missing watermarks or changed history coverage also withhold output. A new run rebuilds only permitted evidence.

Public `getReport`, `getReportCells` and `exportAggregateReport` return only the frozen safe manifest/status and allowlisted aggregate cells. They expose no raw source rows, computation keys, learner identifiers, prompts, answers, private scorer payloads or unrestricted queries. Personal export retains its separate authority and allowlists. Internal source functions have no public raw-data wrapper.

The table-backed fixtures exercise nine owners, several bounded pages, negative gain, missing/unscored endpoints, ordinary blocked claims, post-watermark writes, replays, page faults, overflow, grant attacks and source/account/integrity loss. Their arithmetic is hand-calculated in test comments: 60 to 40 is -20 percentage points; missing both endpoints contributes [-100,100]; cold 60 with missing delayed contributes [-60,40]. These are application accounting checks, not real learning, sample adequacy, scorer/form validation or baseline capture.
