# C4 capability-off parity sweep

Baseline: `58d2ae62238a86b60ce467716c121e6829813fcd` (`origin/dev` when this sweep ran). Scope: the full production diff from `origin/dev` through PR #514 production head `5b780e86d066ec2eaf802756b71aadfe66542c33` (later commits change only docs and tests), including Convex, Nitro, actions, worker callers, shared modules and app callers. No worker implementation files differ from this baseline; their changed callers are listed below. Test-only changes are excluded from the behavior inventory.

The inventory groups a check and its associated result/error together; separate entry points and separate kinds of bounds are separate rows. Counts: **141 gated, 19 proven-same, 13 C4.1 always-on, 1 writer-compatible scheduling projection**, plus **8 #515 always-on** map-contract entries. These are code-review dispositions, not a claim of exhaustive state-space testing.

`Gated` means responses must be enabled for the new check/withholding/accounting/transport to affect an existing entry point. Existing ownership, retained-response privacy, personal-export authorization, quota/rate limits and publisher validation already present at the pin remain. `Proven-same` identifies the unchanged dev rule or the restored exact rule. Only the omission of private assessment material is the C4.1 exception; scheduling preferences and results are not private assessment material. The fixed field allowlists retain writer-valid public data. #515 remains always on by the owner's decision. Signing is optional off and never changes delivered content.

The sweep searched added and removed hunks for limits, `take`, throws, required/optional validators and argument checks, returned shapes, null/empty/cleared fields, authentication/ownership, statuses and new call sites. It also inspected the shared gates and each changed production file; raising an off cap to another cap was not treated as parity. Off collection paths now use dev's `collect()` where dev did.

## Differential evidence

`node scripts/c4-record-dev.mjs` runs the real registered Convex functions through `convex-test` and imports the actual Nitro handlers. Its Vite loader replaces production module sources and their production dependencies with `git show <pin>:<path>` from the baseline. It retains only the current additive storage schema so legacy and newer optional provenance rows can be seeded together. The lockfile/runtime, deterministic seed, frozen clock, identity and provider/R2 stubs are the same for both runs. No provider or remote deployment is called.

The recorder writes complete JSON values, including error/status and pagination metadata, to `tests/fixtures/c4-off-parity/dev-58d2ae62.json`; normal tests only read that file. Expected bodies are never obtained from the current implementation. New Delivery/replay aliases have no dev registration, so their unwrapped body is compared to the recorded original query result. Optional new signing is tested separately. Ordinary malformed legacy fallback text is compared against dev; always-on private-fallback regressions explicitly bind the activity to a held-out assessment context. The Journey source contract is compared in full; its assessment/map/plan envelope intentionally uses C4.1 fixed projections and has separate omission regressions rather than claiming raw-dev envelope parity.

The differential includes unsigned/v1/signed-unknown/deleted-source/invalid chat and export; every affected teaching/copy query and delivery alias; anonymous and owner shares; private media/cache Nitro handlers; 101 interjections, 65 course links plus outline/section handlers, 202 cards, 101 Audio list entries, 65-source folder resolution; accepted/stale/deleted/unavailable Adaptive evidence through public/internal RPC; worker inputs/publication without new auth; invalid legacy card metadata and oversize publication; actual flashcard/topics/Quiz/course/chat/RAG generation handlers with provider stubs; missing arguments, extra legacy fields, missing clients, raw citations and provider/stream status errors. Enabled-boundary suites retain their fail-closed assertions. The foreign-source Quiz denial test explicitly enables responses; its off counterpart is compared against dev. The legacy thread purpose assertion is restored to the pinned dev value.

To reproduce the red comparison, set `C4_PARITY_IMPLEMENTATION_PIN=55bbd8a4f11405115d1de3b2009a711869f889f6` and run Vitest with `scripts/c4-record-dev.config.ts`; this executes the earlier production source against the same golden results without rewriting them. That run failed 32 of 111 tests, including all four reproduced findings. The fixed implementation passed all 111 differential tests (143 recorded results). Final required checks are reported with the final head.
