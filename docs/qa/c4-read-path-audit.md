# C4 teaching read audit

## #573 Today pointer amendment

The [serial API amendment](../plans/learn-v2-c1-public-api-contract.md#573-serial-amendment-today-points-to-canvas) applies to assignments enrolled into the Canvas flow through Today/deep link. The new default-off `todayCanvasChecks` capability selects new enrollment; existing Today assignments keep C5's entry, delivery and acceptance, while frozen Canvas assignments keep their pointer after rollback. Responses remain required. `learnV2Today.getCheckPointers` and `getToday.checkPointers` are `summary_or_own_work`: a closed opaque reference/state/owned Canvas destination projection, without question, answer, key, rubric, score or feedback. Discovery is independent of active sessions, so sealing a dedicated check does not remove its pointer. It reads at most eight opportunities from the existing owner index per page, returning `isDone` and `continueCursor`. Follow continuation pages even when a page has no valid pointers; historical results never exhaust a lifetime candidate cap. Today projects its session first and reserves 64 remaining reads per pointer, including bounded reflow ancestry. Insufficient headroom returns `pointer_page_budget` with no checks and `isDone: false`; start a separate `getCheckPointers({})` invocation. Resource exceptions still propagate.

Today preparation records the real Today/deep-link entry point and `v2_canvas` execution flow without a grant. It validates the full published lesson at the shared publication bounds, then uses one temporary enrollment reference that is replaced by the measurement plan atomically. The ordinary Canvas preparation branch is unchanged. Canvas attachment, canonical sealing and saved-ID scoring retain their existing admission and flow checks. Today session-content reads return no Canvas-owned check body or saved answer. Missing Canvas admission produces no pointer or destination and records prospective non-admission; historical flows are never rebound. Pointer reads validate current owner/thread/activity/replay, pilot, scope, protocol and lifecycle metadata without deep claims, family-member or source traversal. Source revocation can preserve the route; Canvas independently denies content under its full evidence/disclosure checks. Lost Canvas authority removes the pointer; invalid saved-result metadata yields an unconfirmed state while the destination remains valid.

The changed readers share C5's invocation-local measurement context. No catch is added, resource exceptions propagate, and the existing item/evidence/request bounds remain. One additive assignment index discovers frozen Today/deep-link Canvas cohorts during rollback; no stored field or version validator changes. Registered journey, refresh, dedicated-session closure, no-Canvas, flow, toggle, six/twelve-family native-limit paging and 17/32-claim preparation controls are in `convex/learnV2TodayPointers.test.ts`. Existing C4 golden files remain unchanged; production admission and post-seal teaching remain separately gated.

Scope: public Convex query registrations and content-bearing mutation/action/HTTP results for PR #514, following the 2026-11-21 capability-off compatibility decision. This inventory describes code and local regression coverage; it is not a deployment or provider validation.

The responses capability remains default-off; enabling it remains gated by #559. While it is off, existing teaching reads, chat history, shares and exports follow `dev`, including legacy content without retained provenance and copies whose sources are no longer present. New signing is optional while off and never changes visible content. RAG streams bypass the new provenance buffering and limits while off; the existing provider chunks remain unchanged.

When responses are enabled, new message writes are verified: v3 binds owner, role, exact content, every source field and the stored scope. Assistant writes require a server receipt. Convex signs learner prose with unknown teaching scope. New client model/audio context is stripped. Replay checks the retained receipt and returns stored strings without normalization. Legacy v1, unsigned teaching, v2 empty/folder-only references and v3 unknown scope have no source authority; no conversation-folder fallback is used. When responses are enabled, signed source references are also resolved against current document/folder ownership, access, retained source identities/snapshots/excerpts and teaching lineage before replay, including ordinary history. Revocation withholds assistant/source content while preserving valid learner prose. Message export uses the same checks after its mandatory export authorization and reports `evidence_unavailable`; a fresh authorization cannot restore revoked quotes. Access validation is bounded to 64 references, 64 retained identities and 64 snapshots, with the existing folder, privacy-read and lineage budgets. It never repairs or re-pins a stale lineage during replay.

Schema changes are additive. `messages.helpScope` accepts v3 with an explicit `known`, `unknown` or `independent` state and nullable references, while retaining v1/v2 for existing rows. `quizAnswerAssessments.questionSnapshot` adds optional `scopeVersion` and `sourceDocumentId`; new snapshots bind their original source rather than accepting a replacement question's source. `reviewItems.sourceVersionId` records the immutable flashcard version used by new copies. With responses enabled, legacy copies without that origin remain unavailable. With responses enabled, these retained origin fields are omitted from learner projections. Off reads retain the dev row shape. No backfill, table, index, flag activation or migration is introduced.

With responses enabled, unknown is never an empty source set. All replay/export aliases withhold unknown assistant text, excerpts, source names, model/context fields and quotes, report `evidence_unavailable`, and preserve valid learner prose. Fresh retrieval or history-bearing answers never receive an independent receipt. History-bearing RAG signs `unknown` with null references; persistence stores a signed unavailable tombstone, not an unscoped protected copy. Independent receipts exist only for new general answers that used neither retrieval nor history, and still cannot establish irrelevance during an open check. v2 known document receipts retain exact-byte verification and live authority checks.

Queries cannot create exposure. With responses enabled, after admission, a teaching query with relevant formative work reads its normal projection dependencies and throws `help_delivery_required` with an opaque HMAC revision, never the body. The revision covers that projection, its current source scope and the bounded open-opportunity identities/revisions. The existing subscription re-requests its paired delivery mutation when the signal changes, reusing its delivery key; exposure remains deduplicated per key, help kind and opportunity even when the current source set changes. Current scope is always revalidated and is not an authorization supplied by the receipt. This applies through the shared wrapper to every `delivery` and `media_locator` row below. Held-out denial occurs before the content handler. Admission precedes construction and dispatch; the mutation records assistance only for a substantive returned body. Empty/unavailable projections and failures roll back or create no delivered exposure. Denied mutations return an admission with a null value, preserving non-delivered denial records. Scope follows source IDs, source manifests and bounded lineage dependencies/origins. Missing provenance and exhausted bounds deny rather than infer irrelevance from a container.

With responses enabled, every wrapped read and its delivery/preparation alias resolves current authority through `teachingReadScope`, even without an open opportunity. With responses off, the wrapper calls the existing handler without new scope resolution, admission, accounting or privacy-read budgets; aliases return the same ordinary value. Teaching producer/source adapters and cached task projections follow the same gate. With responses enabled, the wrapper accepts only scopes validated within that invocation; null, empty targets, folder-only scope, exhausted bounds or a failed dependency cannot authorize teaching. Scope validation checks live ownership/status, source retention and tombstones, current document access, every active artifact key's exact payload/lineage and its transitive source/origin pins using the existing pure C4 admission guard. Delivery handlers receive a read-only database context, so existing producer helpers cannot re-pin or repair a publication while reading it. The same authority resolver protects copied teaching in authorized export; source-free legacy copies become unavailable tombstones while learner answers remain available.

Legacy deck, Audio-list, interjection-history, course-source and folder-scope reads preserve dev ordering and collection behavior while off, including `collect()` where dev used it. The stricter teaching-specific limits apply only while enabled. The [A6 off-parity sweep](c4-off-parity.md) lists the full production diff inventory, check dispositions and pinned dev differential procedure.

Each enabled authority resolution uses the existing 3,072-read privacy budget, 64 source references, 64 lineage nodes, 256 edges and 512 targets, depth 8 and 1,024 visited result rows. Per-kind ranges have explicit overflow checks (200 questions/cards/assessments, 32 claims, 16 session blocks, 8 supports/origins). Overflow withholds teaching. Export pages remain capped at eight rows and reuse the request's budget.

With responses enabled, private media is prepared before R2 access, then a server-held credential is required for authenticated media delivery before forwarding each chunk. A learner cannot forge that accounting acknowledgement. The same receipt is reused for all chunks, so partial delivery counts once and later failure retains that fact. No chunk is prefetched into the downstream stream. This costs one bounded Convex delivery mutation per upstream media chunk; each invocation revalidates current admission, lineage and source pins. Metadata preparation and failed fetches record no delivered assistance. While off, media routes use the original query and proxy the existing body without a delivery mutation or per-chunk admission.

The four share-token query families and their aliases explicitly permit anonymous ordinary teaching. Their original live token, publication and owner checks always apply; the new lineage and source-pin checks apply with responses enabled. Anonymous reads do not use or account against the publisher's opportunity. With responses enabled, authenticated reads continue through the viewer's contextual admission; an owner cannot bypass their own held-out check by using their share token.

The personal export/original-file exception follows [the disclosure resolution, section 3.5](https://github.com/wescodess/budds/issues/373#issuecomment-6651824980): do not suspend lawful export during an open check; require its existing bounded export authorization and contamination/unknown accounting. Those endpoints do not become unaccounted teaching reads.

With responses off, existing teaching, history, shares and personal exports retain the C4 parity behavior. `convex/learnV2MeasurementReports.test.ts` covers aggregate privacy canaries, anonymous/foreign/different-issuer denial, scoped grants, deletion and revocation; the C4 differential suites cover existing learner paths.

The C5/C6 integration preserves both initial-link and later-link writers' transactionally recorded `firstCheckClaim` back-reference and sequence one on the earliest original. C6 continues to classify missing back-references as `first_slot_claim_missing` and reject conflicting identities. C5 eligibility facts now capture the owned mastery state when a clocked original first becomes eligible, and preserve that captured state through binding, delivery, scoring and replacement. Earlier eligible facts without a captured state remain `unknown`; current mastery cannot supply historical eligibility. These additional lookups and fact fields are responses-gated, and use C6's existing optional storage field.

C6's configuration stratum includes the scorer configuration digest. Parser v2, receipt guard v3 and transport v2, plus the current pinned guard implementation, change that digest from earlier branch configurations. These strata are distinct; no saved configuration is repinned. This change is accepted before any production scorer inventory exists.

Reserve replacement keeps its recorded `replacementBinding`, secondary sequence zero, and the original allocation/first-slot clock. It cannot replace an accepted original and emits opportunity facts rather than response-integrity facts. A replacement therefore leaves an already sealed source snapshot unchanged. Subsequent response evidence purging emits an `integrity` fact; C6's owner/kind/sequence revocation index withholds the report as stale. C5's session-purpose index and optional replacement record coexist with C6's report-audit storage, revocation index and optional captured states; no required field or backfill is introduced.

`convex/learnV2C5ReportsIntegration.test.ts` drives real registered cold/ordinary/day-7 delivery, acceptance and scoring into bounded C6 extraction, sealing and audited reads. It covers pass/fail, one reserve within a cohort, one claim per learner, the original first-slot identity, immutable snapshot access after replacement, and integrity revocation. Cohorts satisfy C6's publication thresholds; no disclosure threshold is relaxed. Historical-unknown and responses-off controls cover the eligibility writer. The C5 and dev C4 goldens are retained without regeneration. Canvas collection remains disabled pending [C5.6 #535](https://github.com/wescodess/budds/issues/535); synthetic publication/scorer transport establishes local behavior only.

## Delayed-check cron and publication failure recovery

`learnV2MeasurementDueWork.sweepDelayedCheckEligibility` is an internal, metadata-only cron entry point, registered every minute. Responses, enrollment, delivery, the V2 rollout flag and a frozen protocol are conjunctive gates before database reads, writes or scheduling. A single-row lease admits one chain; a tick during a live lease returns `busy`, and every step rotates the lease token so a stale step stops without writes. Each chain covers the window from the last completed target to the tick time and visits only due edges: new owner watermarks by creation time, `preparing` opportunities by open time (before their nominal due minute), and `preparing`, `ready` and `test_open` opportunities by close time. Each page visits at most 16 rows, schedules at most 16 owner jobs and one continuation, and preserves a fixed target. A tick with nothing due schedules nothing. Owner jobs recheck the gates and unique enabled measurement catalogue and process one assignment per transaction with sequence-checked continuations. A disabled learner is visited once per due edge. Duplicate jobs use the existing opportunity, binding and eligibility-event identities; OCC retries do not allocate another original slot or grant. C6 report pinning advances an owner's coverage to the cutoff only when its last complete sweep has no unapplied open or close edge before the cutoff. No client return or disclosure grant is required for materialization.

Today and Canvas retain their flow-specific discovery and grant authority. On-time materialization binds the assigned horizon; teaching is denied while that check is open. Help admission excludes elapsed windows by index before its bound, so an overdue `preparing` row cannot indefinitely deny teaching. Never-playable expired checks record `system_due_work_late`; C6 preserves the reason and counts a missing delayed outcome, not a learner abandonment. An on-time playable check that expires retains `missed_window`. A system-late dedicated binding is cancelled without a learner missed timestamp. Original allocation, response pins and first-slot links are unchanged.

Storage additions are optional opportunity-fact `reasonCode`; four opportunity indexes (phase/open time, phase/close time, owner/phase/open time and owner/phase/close time); a source-watermark creation-time index; and the global `learnMeasurementDueWorkCursors` lease row, which holds no learner data. Existing fields and indexes remain. No migration, flag activation, scorer identity change or C4 golden edit is required. C6 reducer code advances to `learn-v2.report-code.c6.2.v7` for the new reason semantics, which apply to episodes and first-check claims alike; prior saved code identities are not repinned, and the offline replay boundary rejects v6 inputs. Registered cron tests cover continuation, single-flight ticks, lease takeover with a stopped stale chain, idle ticks that schedule nothing, disabled learners visited once per edge, pin-time coverage with and without an unapplied edge, zero-read/write/schedule off states, early-open windows, non-returners, retained bindings, elapsed-row help admission, overlapping horizons at maximum published inventory under native limits, and a sealed C6 system-late report.

The final session-content commit catch restores dev's off-state failure receipt and immediate retry. With responses on, it records the same lease/revision-checked failure state before rethrowing unexpected or resource errors. No failed commit becomes a successful publication.
