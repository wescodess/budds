# Phase C1 public API contract

API version: `learn-v2.public-api.v1`. Implements [C1.3 #423](https://github.com/wescodess/budds/issues/423) for [C1 #413](https://github.com/wescodess/budds/issues/413). Report output is `learn-v2.measurement-report.v3`; source is v3; query and metric definitions remain v1. This contract adds no active response, delivery, scoring, assistance or report writer.

The accepted [baseline](https://github.com/wescodess/budds/issues/359#issuecomment-6651298918), [lifecycle](https://github.com/wescodess/budds/issues/360#issuecomment-6651303610), [responses](https://github.com/wescodess/budds/issues/363#issuecomment-6651831618), [items](https://github.com/wescodess/budds/issues/364#issuecomment-6651739355), [reports](https://github.com/wescodess/budds/issues/366#issuecomment-6652156993), [disclosure](https://github.com/wescodess/budds/issues/373#issuecomment-6651824980) and [scorer identity](https://github.com/wescodess/budds/issues/380#issuecomment-6651838342) resolutions remain binding.

## Registered boundaries

Argument and return validators live in `convex/lib/learnV2PublicContract.ts`. They are importable by application and server adapters and contain no private scorer or source loader. Existing shared schemas supply semantic validation, including original-envelope bytes, finite numbers, exact response text, code-unit limits and URL-safe command keys. Invalid wire input produces a bounded generic error. The new public functions accept no owner, cohort, scorer, phase, trusted grant object or draft payload.

Authentication derives ownership from `tokenIdentifier` through `requireAuth`, including the account-deletion tombstone. Targeted calls check the record and its owning Void/Blueprint/objective/plan/session or standalone thread/activity. Canvas attribution retains the additional adaptive access conjunction; a wrapper cannot remove it. Unauthenticated, foreign, missing or mismatched authority is denied without returning stored payloads. A new handler never returns a successful save, grant, terminalization, score or report from an unimplemented operation.

Delivery mutations and prompt reads are separate. A future grant result is only a reference; a query cannot create the first grant. Future state/score returns use the C1.2 own-work and safe-result DTOs. Private keys, rubric criteria, sibling forms, seeds, source locators and provider payloads are absent from the new public return validators. The report request identifies a server-managed viewer grant, not a client-chosen cohort/epoch; the grant supplies its authorized scope. Reads recheck its scope, revocation, time and deletion state. Report pages reserve the bounded aggregate DTO; there is no public raw-source adapter or self-grant command.

## Frozen report output v3

Report references, disabled receipts, sealed manifests, cell pages and aggregate exports use `learn-v2.measurement-report.v3`. Request queries and source facts use `learn-v2.measurement-report-query.v1` and `learn-v2.measurement-report-source.v3`; VLG and false-mastery definitions remain v1. Other public APIs retain `learn-v2.public-api.v1`. Old report-output v1/v2 and source v1/v2 shapes are rejected. These endpoints still return disabled status and perform no write.

`learnReportMetricValidator` in `convex/lib/learnV2MeasurementReportContract.ts` supplies the exact stored/public/exported cell fields. Before a later writer or adapter uses them, `learnReportMetricSchema` and `validateLearnMeasurementReportCells` enforce bounded integers, finite estimates, nested counts, disjoint totals, null/reason states and original-envelope/page bytes. Convex's declared validators enforce the same closed output structure. Cells remain aggregate-only, without learner/assignment/attempt rows or protected payloads.

[#511](https://github.com/wescodess/budds/issues/511) also narrows both `replacements.secondary` and `sensitivity.excludingFlagged`: neither may strengthen an unknown parent population/source state or its validity (verified → provisional → unknown → quarantined). Quarantined parent status requires quarantined sub-estimate validity; unknown-source parent status requires unknown sub-estimate source coverage. Flag exclusion must retain at least `max(0, observed - eitherFlagged)` original pairs or checked claims, and may lose at most one contributing learner per removed observed row. Stronger sub-estimates are rejected, while equal or weaker evidence remains accepted. The fixture's cold-conditioned missing contribution and full arithmetic are recorded in the storage mapping. These refinements change no metric definition, result, score or mastery rule.

Public cell pages, aggregate exports, stored cells and the owner-watermark audit snapshot reuse `convex/lib/learnV2MeasurementReportContract.ts` for the audit's closed structure. Shared schemas apply the integer, null/coverage and parent/sub-estimate refinements before persistence or publication. Unknown owner history requires an unknown/null legacy audit; complete history may still carry an unknown/null audit. `validateLearnMeasurementReportCells` also requires identical `legacyIndependentAudit` coverage and count across every cell on a page. Personal and ZIP exports still withhold the audit and source snapshots; account/source deletion and run invalidation use the existing registrations.

Scorer alias policy `learn-v2.scorer-identity-policy.v2` permits a verified alias only when its `requestedModel` and `configurationDigest` both match the frozen binding; unrelated flat alias lists cannot authorize a different returned model (#380). A valid measurement-only snapshot may carry only `retained_promotion_ineligible` when measurement eligibility is true and mastery eligibility is false; contamination/evidence/unknown exclusions still cannot accompany valid credit. This preserves delayed measurement below Independent without changing the mastery rule (#366 §2 / #364 §5).

C6.1 counts `considered` candidates and `notAdmitted` assignments per **distinct `assignmentId`**, never per row. Both status fields remain available to distinguish `not_admitted` from `protocol_not_frozen`. Storage enumerates a non-admitted assignment once without an allocation; its sole source inventory row uses canonical `horizonDays: 7` only as an envelope placeholder, with `assignedDay7 = assignedDay30 = false`. It contributes no horizon denominator or horizon stratum. Admitted episode horizons require the corresponding assignment flag; three-case allocations assign both horizons and two-case allocations exactly one. The `(assignmentId, horizonDays)` identity detects repeats, and every row of one assignment must retain the identical full snapshot; inconsistent admission pins use `conflicting_assignment_snapshot`. A considered candidate and a blocked not-admitted candidate can each reconcile as complete and remain distinguishable.

Only an `independent_application` pass under the pinned mastery transition can establish Independent. Source endpoint kinds exclude it, so any claim basis found in the run's result-attempt index returns `invalid_claim_basis` with one lookup. An absent ordinary V2 basis remains a canonical writer obligation, including valid unassisted passage, attainment time and pinned mastery revision. At the maximum 10,000 episodes / 64 MiB input, reconciliation is action or offline work, never query or mutation work.

The [source storage mapping](learn-v2-c1-storage-contract.md#517-report-source-v3) defines the exact SHA-256/JSON key derivation, roster and cross-page obligations. Writers use `deriveLearnReportLearnerKey` / `deriveLearnReportComputationKeys` with the run ID, authenticated full owner `tokenIdentifier` and the settled mastery scope (owner + Blueprint revision + objective). They recompute these keys from canonical identities, never vary them per row. `reconcileLearnReportSourceRows` returns only completeness and reason codes; any missing watermark, duplicate/conflict or inconsistent assignment/key binding is incomplete. Missing/unknown owner audit makes the cohort legacy audit unknown/null, and cross-page audit equality remains a run-level check.

The shared schemas enforce acceptance/strata/policy semantics; `learnV2MeasurementReportContract.ts` owns the structural validators reused by storage. Cells, public pages, safe manifests, aggregate exports and logs never include these computation keys. Both personal export paths withhold snapshots through their existing allowlists. Regressions cover public return rejection, both exports, diagnostics and log omission. No report arithmetic, writer, migration, backfill, flag or provider call is introduced.

The batch arguments are `{ artifacts: [{ reference, validationId }], expectedCatalogRevision }`; 1–50 distinct members share one comparison revision, one charged read budget and one catalogue advance. A transaction gets one batch: its advance makes any second batch's comparison stale. A producer must reuse the stable case: duplicate scenario or solution fingerprints make both artifacts unavailable.

Create `const budget = createArtifactLineageReadContext(ctx)` once per producer transaction and use `budget.ctx` for every lineage helper. Its live `readUsage` includes repeated reads and failed lookups; the 4 MiB allowance is shared across batch members, leaving 12 MiB for the producer's separate work. Read liveness and exact pins again inside every persistence/cache/share mutation, including cache hits. Never accept a preflight result as write authority.

#### #525 preparation and C4.3 producer call guide

`prepareAndRegisterInstructionalArtifacts(ctx, input)` derives the session owner. `prepareAndRegisterInstructionalArtifactsForOwner(ctx, userId, input)` also requires that exact authenticated owner. Capability-authorized or scheduled producers use `prepareAndRegisterInstructionalArtifactsForRecord(ctx, ownerRecord, input)`, with the existing document/Audio Overview job authority checks. These are unregistered helpers, never client or worker endpoints.

The strict input is `{ artifacts: [{ artifact: { kind, id }, key, origins: [{ reference, transformation }], sources: [dependency] }] }`. IDs already exist in the producer's publishing mutation. The producer supplies complete server-built source/origin references from its authorized generation context; the helper additionally derives document/snapshot links from the actual stored output. There are no output content, classification, case, validation, policy, revision, digest, adapter or novelty arguments. Empty `origins` means fresh output; a copy/rewrite/summary must retain its actual origin. Document uploads cannot claim derived origins. The result is `{ version, lineageIds, references, catalogRevision, readUsage }`, with references computed from the persisted content. Preparation rereads the current catalogue, seals each content/graph decision and registers the complete set under one advance. Propagate every error out of the producer mutation so content, new graph rows and registration roll back together.

First create one `createArtifactLineageReadContext(ctx)`, then use its context for scope, input lookup and preparation. `isArtifactRegistrationRequired(ctx)` and `isArtifactRegistrationRequiredForOwner(ctx, userId)` serve sessions; `isArtifactRegistrationRequiredForRecord(ctx, ownerRecord)` serves identity-less writers. They return true only for `learnAssessmentCatalogs.measurementCapability.enabled === true`. Missing catalogue/capability or disabled capability means unenrolled. C4.3 skips output registration when false; input guards stay always on. No runtime switch, enrollment writer or capability enablement is introduced. Enrollment must supply the prospective history basis after owner approval under #362; earlier unregistered teaching remains unknown history outside that basis.
