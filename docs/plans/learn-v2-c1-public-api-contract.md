# Phase C1 public API contract

API version: `learn-v2.public-api.v1`. Implements [C1.3 #423](https://github.com/wescodess/budds/issues/423) for [C1 #413](https://github.com/wescodess/budds/issues/413). Report output is `learn-v2.measurement-report.v3`; source is v3; query and metric definitions remain v1. This contract adds no active response, delivery, scoring, assistance or report writer.

The accepted [baseline](https://github.com/wescodess/budds/issues/359#issuecomment-6651298918), [lifecycle](https://github.com/wescodess/budds/issues/360#issuecomment-6651303610), [responses](https://github.com/wescodess/budds/issues/363#issuecomment-6651831618), [items](https://github.com/wescodess/budds/issues/364#issuecomment-6651739355), [reports](https://github.com/wescodess/budds/issues/366#issuecomment-6652156993), [disclosure](https://github.com/wescodess/budds/issues/373#issuecomment-6651824980) and [scorer identity](https://github.com/wescodess/budds/issues/380#issuecomment-6651838342) resolutions remain binding.

## Registered boundaries

Argument and return validators live in `convex/lib/learnV2PublicContract.ts`. They are importable by application and server adapters and contain no private scorer or source loader. Existing shared schemas supply semantic validation, including original-envelope bytes, finite numbers, exact response text, code-unit limits and URL-safe command keys. Invalid wire input produces a bounded generic error. The new public functions accept no owner, cohort, scorer, phase, trusted grant object or draft payload.

Authentication derives ownership from `tokenIdentifier` through `requireAuth`, including the account-deletion tombstone. Targeted calls check the record and its owning Void/Blueprint/objective/plan/session or standalone thread/activity. Canvas attribution retains the additional adaptive access conjunction; a wrapper cannot remove it. Unauthenticated, foreign, missing or mismatched authority is denied without returning stored payloads. A new handler never returns a successful save, grant, terminalization, score or report from an unimplemented operation.

Quarantined parent status requires quarantined sub-estimate validity; unknown-source parent status requires unknown sub-estimate source coverage. Flag exclusion must retain at least `max(0, observed - eitherFlagged)` original pairs or checked claims, and may lose at most one contributing learner per removed observed row. Stronger sub-estimates are rejected, while equal or weaker evidence remains accepted. The fixture's cold-conditioned missing contribution and full arithmetic are recorded in the storage mapping. These refinements change no metric definition, result, score or mastery rule.

Personal and ZIP exports still withhold the audit and source snapshots; account/source deletion and run invalidation use the existing registrations.

Scorer alias policy `learn-v2.scorer-identity-policy.v2` permits a verified alias only when its `requestedModel` and `configurationDigest` both match the frozen binding; unrelated flat alias lists cannot authorize a different returned model (#380). A valid measurement-only snapshot may carry only `retained_promotion_ineligible` when measurement eligibility is true and mastery eligibility is false; contamination/evidence/unknown exclusions still cannot accompany valid credit. This preserves delayed measurement below Independent without changing the mastery rule (#366 §2 / #364 §5).

C6.1 counts `considered` candidates and `notAdmitted` assignments per **distinct `assignmentId`**, never per row. Both status fields remain available to distinguish `not_admitted` from `protocol_not_frozen`. Storage enumerates a non-admitted assignment once without an allocation; its sole source inventory row uses canonical `horizonDays: 7` only as an envelope placeholder, with `assignedDay7 = assignedDay30 = false`. It contributes no horizon denominator or horizon stratum. Admitted episode horizons require the corresponding assignment flag; three-case allocations assign both horizons and two-case allocations exactly one. The `(assignmentId, horizonDays)` identity detects repeats, and every row of one assignment must retain the identical full snapshot; inconsistent admission pins use `conflicting_assignment_snapshot`. A considered candidate and a blocked not-admitted candidate can each reconcile as complete and remain distinguishable.

Only an `independent_application` pass under the pinned mastery transition can establish Independent. Source endpoint kinds exclude it, so any claim basis found in the run's result-attempt index returns `invalid_claim_basis` with one lookup. An absent ordinary V2 basis remains a canonical writer obligation, including valid unassisted passage, attainment time and pinned mastery revision. At the maximum 10,000 episodes / 64 MiB input, reconciliation is action or offline work, never query or mutation work.

The [source storage mapping](learn-v2-c1-storage-contract.md#517-report-source-v3) defines the exact SHA-256/JSON key derivation, roster and cross-page obligations. Writers use `deriveLearnReportLearnerKey` / `deriveLearnReportComputationKeys` with the run ID, authenticated full owner `tokenIdentifier` and the settled mastery scope (owner + Blueprint revision + objective). They recompute these keys from canonical identities, never vary them per row. `reconcileLearnReportSourceRows` returns only completeness and reason codes; any missing watermark, duplicate/conflict or inconsistent assignment/key binding is incomplete. Missing/unknown owner audit makes the cohort legacy audit unknown/null, and cross-page audit equality remains a run-level check.

The shared schemas enforce acceptance/strata/policy semantics; `learnV2MeasurementReportContract.ts` owns the structural validators reused by storage. Cells, public pages, safe manifests, aggregate exports and logs never include these computation keys. Both personal export paths withhold snapshots through their existing allowlists. Regressions cover public return rejection, both exports, diagnostics and log omission. No report arithmetic, writer, migration, backfill, flag or provider call is introduced.

Case usage classes are permanent and the predecessor keeps its own bindings as history, so everything taught stays recorded as `instructional`. #### #525 preparation and C4.3 producer call guide

`prepareAndRegisterInstructionalArtifacts(ctx, input)` derives the session owner. `prepareAndRegisterInstructionalArtifactsForOwner(ctx, userId, input)` also requires that exact authenticated owner. Capability-authorized or scheduled producers use `prepareAndRegisterInstructionalArtifactsForRecord(ctx, ownerRecord, input)`, with the existing document/Audio Overview job authority checks. These are unregistered helpers, never client or worker endpoints.

The strict input is `{ artifacts: [{ artifact: { kind, id }, key, origins: [{ reference, transformation }], sources: [dependency] }] }`. IDs already exist in the producer's publishing mutation. The producer supplies complete server-built source/origin references from its authorized generation context; the helper additionally derives document/snapshot links from the actual stored output. There are no output content, classification, case, validation, policy, revision, digest, adapter or novelty arguments. Every origin must resolve as already published teaching with the same classification as the output; a copy/rewrite/summary retains its actual origins, while empty `origins` means original output. Document uploads cannot claim derived origins. The result is `{ version, lineageIds, references, catalogRevision, readUsage }`, with references computed from the persisted content. Preparation rereads the current catalogue, seals each content/graph decision and registers the complete set under one advance. An identical-content replay runs the same recursive source, origin and linked-component checks and the reservation recheck before returning its existing receipt. Added sources or origins follow ordinary succession, even when the content projection is unchanged. Every batch component's complete active lineage, across all keys and representations, must remain non-restrictive and available. One shared helper inspects sibling-key, declared teaching-origin and provisional re-index graphs and recursively admits their dependencies. It keeps retained sources/origins separate from the root's current projected components. Retained dependencies and all components reached through them must already admit as registered, even when they are also being prepared in the batch; a pending edit does not repair an origin. Only sibling inspection exempts its root's current linked components that are direct outputs of this batch, matching the ordinary preparation rule. A reference reached through a retained origin on a different artifact must still pass retained admission when it is also currently projected. Sibling origins at another key of the same artifact are removed before that partition; their current projected components may receive the same-batch exemption. Writers must still re-register every affected current key in the publishing mutation. ## #539 server-derived help admission

`learnV2Assistance.admitHelp` is an authenticated mutation with the separate version `learn-v2.help-admission.v1`. Its closed input is `{ version, kind, idempotencyKey, scope }`: `kind` is chat/search/source/audio/replay; the key uses the existing 16–128-character command format; `scope` is null or `{ references }` with 1–64 owned conversation, folder, document, source-snapshot, Void, thread, Audio Overview or Audio job references. A route must pass the complete scope it verifies and actually uses, including every selected folder/document. An optional session ID, client phase, client opportunity, unrelated boolean, cached receipt or supplied text is never context authority. Void/thread references cover the native search and Canvas contexts; overview references resolve the existing episode/job and source manifest before interjection content is read.

Results are `{ version, status: ordinary }`, `{ version, status: authorized, authorizations: [{ assessmentOpportunityId, authorizationId }] }`, or `{ version, status: denied, reasonCode: test_open | disclosure_unknown | unavailable }`. Multiple relevant opportunities require one atomic admission; a denied member prevents every delivered-help exposure. The ordinary branch has no exposure ID and writes nothing. It means no relevant open check, not permission to disclose an item, source or protected producer lineage. Each route retains its normal owner/source/lineage authority.

`convex/lib/learnV2HelpAdmission.ts::admitLearnHelpForOwner` derives the authenticated owner and uses `by_userId_and_phase` for preparing/ready/test_open opportunities. At most eight owner-wide open rows are admitted to evaluation; the ninth denies as unknown. Scope resolution reads at most 64 snapshots per Void, 64 explicit references or audio sources, and eight folder ancestors; missing or excessive authority fails closed. A scope is unrelated only when it shares no Void, thread, folder/ancestor scope or source identity with any open opportunity. Backing documents and canonical source identities follow sources across folders and Voids. Sibling folders do not become related merely because they have a common parent. No resolvable scope with an open check is unknown. Every invocation rechecks current state before replaying an exposure.

Response capability off means no new opportunity can be open and preserves ordinary help without an exposure or new capability. `authorizeAssistance` remains the opportunity-bound API, now calling the existing C2 helper; disabled there is always denied. It is never converted into ordinary permission.

C2's `prepareLearnResponseAssistanceForOwner` performs the existing scope/evidence/purpose checks and supplies a commit closure bound to that same mutation context. The admission helper prepares every relevant opportunity before invoking any closure, so a later denied member cannot leave an earlier delivery behind. The closure is server-only, never serialized, stored or accepted in an RPC. Exposure and opportunity reads serialize with response sealing through Convex transaction validation. Denials record requested_denied rather than assistance; sealing removes the row from the open-phase lookup, and later ordinary teaching cannot rewrite the accepted snapshot. No raw question, source body, answer or provider payload is present in these results or exposure fingerprints.

This contract enables no capability, enrollment, UI or producer. C4.2 #430 installs its consumers and executable HTTP/replay tests. The parent orchestrator retains the final C4 review gate.
